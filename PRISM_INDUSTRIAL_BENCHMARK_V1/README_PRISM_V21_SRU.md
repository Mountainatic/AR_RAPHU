# PRISM v2.1 SRU stagewise-routed execution

The implementation is restricted to `SRU_H2S__H5__W1` and
`SRU_SO2__H5__W1`. It preserves the complete C1 shared-data base and writes
only to `results_prism_v2_1_sru`.

## Server

```bash
ssh -p 48643 root@connect.westb.seetacloud.com
```

The configured runtime and immutable C1 data are:

```text
uv executable: /root/AR_RAPHU_AUTODL/.autodl-tools/uv
uv project:    /root/AR_RAPHU_AUTODL
shared C1:     /root/autodl-tmp/PRISM_SHARED_DATA_C1
```

## Server preflight (does not start B0 or E0)

```bash
cd /path/to/PRISM_INDUSTRIAL_BENCHMARK_V1
export PYTHONPATH="$PWD/src"
/root/AR_RAPHU_AUTODL/.autodl-tools/uv run --no-sync \
  --project /root/AR_RAPHU_AUTODL \
  python -m pytest tests -q
```

Historical baseline parquet is neither required nor searched. B0 reruns the
frozen C2--C6 baseline code for the two SRU H5/W1 heads, writes aligned
validation/test per-sample parquet, and freezes their SHA256 values. B0 computes
validation metrics only. It does not compute test metrics or expose test loss to
the v2.1 selectors. The v2.1 model test guard remains E6 -> E7.

## Full automatic chain

```bash
export PRISM_V21_SHARED_ROOT=/root/autodl-tmp/PRISM_SHARED_DATA_C1
export PRISM_V21_OUTPUT_ROOT="$PWD/results_prism_v2_1_sru"
export PRISM_V21_BASELINE_WORKERS=8
export PRISM_V21_THREADS_PER_WORKER=4
export PRISM_V21_MEMORY_GIB_PER_WORKER=4
export PRISM_V21_MEMORY_RESERVE_GIB=8
export PRISM_V21_THROUGH_STAGE=e8
bash RUN_PRISM_V21_SRU.sh
```

The chain is resumable by PASS markers and runs in the fixed order:

```text
B0 -> E0 -> E1 -> E2-K -> E2-C -> E3-W -> E4-A -> E5-Joint -> E6 -> E7 -> E8
```

Set `PRISM_V21_THROUGH_STAGE=b0` to reproduce and hash only the SRU baselines.
Set `PRISM_V21_THROUGH_STAGE=e6` to develop and freeze without opening test.
E7 refuses access unless `V21_SRU_FINAL_FREEZE_MANIFEST.json` is valid. E8
creates metrics, entity metrics, the 500-replicate paired moving-block
bootstrap with Holm correction, audit JSONL files, a final report, manifests,
and the verified ZIP bundle.

B0 and every later stage run as separate subprocesses. Resume uses frozen PASS
markers; an existing non-PASS marker is a hard audit stop. No OOD, non-SRU, or
private CZ task is generated by this chain.

The default CPU profile is `8 workers x 4 BLAS/OMP threads = 32 threads`.
Before any stage starts, the chain reads the cgroup CPU affinity and memory
limit, rejects CPU oversubscription, and reserves a conservative 4 GiB per
worker plus 8 GiB for the parent process/cache. The resolved limits are written
to `RUN_LOG/V21_RUNTIME_PROFILE.json`.
